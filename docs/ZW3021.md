# Torabo-chan：ZW3021追加配線・設定

PAW3222と5キーを維持したまま、HLK-ZW3021の指紋照合による文字列入力を追加する構成です。
指紋登録・文字列設定はUSB接続のChrome／Edgeから行います。
登録後の文字列入力はZMKが選択しているUSB／Bluetooth出力先に送信します。
Bluetooth経由のブラウザー設定はこの構成では無効です。

## 配線

2026-09-27：実機のセンサー側RX/TXが逆になった配線に合わせ、ファームウェアでP0.09をTX、P0.10をRXへ変更しました。
下表は中継基板の印字ではなく、XIAOとZW3021本体の実際の信号の対応です。

| XIAO側 | 追加回路／ZW3021側 | 役割 |
|---|---|---|
| NFC1 / P0.09 | ZW3021 UART-RX | XIAOから送信 |
| NFC2 / P0.10 | ZW3021 UART-TX | XIAOで受信 |
| P0.16 | ZW3021 INT | 指検出、Highで検出 |
| D2 / P0.28 | ロードスイッチEN | HighでVCC-D給電 |
| 3.3V | VCC-SおよびロードスイッチIN | センサー待機電源と主電源の供給元 |
| GND | ZW3021とロードスイッチのGND | 共通GND |

ロードスイッチOUTをZW3021のVCC-Dにつなぎます。D2はEN信号であり、VCC-Dを直接給電するピンではありません。
ENはリセット中に浮かないよう、使用するロードスイッチの仕様に従ってプルダウンしてください。
VCC-Sは3.15～3.6V。電源回路の電流容量・コンデンサーは実際に使うロードスイッチとZW3021の資料に従ってください。

D2にはPCB上でRow1のネット名がありますが、現在の基板ではXIAOパッドのみで、5キーは全てD1/Row0につながっています。
P0.16は利用者が引き出し可能と確認したピンです。Sense版ではマイク信号なので、接続されたマイクとの競合を避けてください。
NFC端子はこのファームウェアでGPIOへ切り替わり、NFCとしては使用しません。
UART1を57600 bps、8データビット、パリティなし、2ストップビットで使用します。

## 実機配線の記録（2026-09-27）

使用する中継基板は **FingerPrint_Module**。
設計データは `D:\OneDrive - スタッフマーケティング株式会社\KiCad\FingerPrint-Module\FingerPrint_Module` にあります。
この基板には **AP22804AW5** があり、FP_ENがHighのとき3V3からVCC-Dへ給電します。
FP_ENには100kΩのプルダウン（R2）が実装される設計です。

### XIAOから中継基板まで

端子名は中継基板の印字／ネット名です。**RX/TXの印字と、現在のXIAOの送受信方向が逆**になっています。
J1はFFC、J3はピンヘッダーで、下表はそれぞれの同じネットの端子番号を示します。

| XIAO | 中継基板の信号 | J3番号 | J1番号 | 現在のファームウェアでの役割 |
|---|---|---|---|---|
| P0.09 / NFC1 | RX / HOST_RX | 4 | 4 | UART TX（送信） |
| P0.10 / NFC2 | TX / HOST_TX | 3 | 3 | UART RX（受信） |
| P0.16 | INT / FP_INT | 5 | 5 | 指検出入力 |
| D2 / P0.28 | EN / FP_EN | 6 | 2 | AP22804AW5のEN制御 |
| GND | GND | 2 | 1 | 共通GND |
| 3.3V | 3V3 | 1 | 6 | VCC-Sと電源スイッチの入力 |

### 中継基板からセンサーまで

最初はJ2を全て同じ番号で接続したとの報告でしたが、その後、実機のセンサー側RX/TXが逆と確認されました。
配線を入れ替える代わりに、ファームウェアでUARTのTX/RXを交換しています。
その実配線に対応する信号経路は次のとおりです。

| 中継基板J2 | ZW3021本体 |
|---|---|
| 1 / 3V3 | 1 / VCC-S |
| 2 / FP_INT | 2 / INT |
| 3 / VCC-D | 3 / VCC-D |
| 4 / HOST_RX（印字RX） | **5 / UART-RX** |
| 5 / HOST_TX（印字TX） | **4 / UART-TX** |
| 6 / GND | 6 / GND |

つまり、現在は **P0.09 → HOST_RX → センサーRX**、**センサーTX → HOST_TX → P0.10** です。
J2を1→1～6→6のストレート配線へ変更した場合は、UART設定も元のP0.10＝TX、P0.09＝RXへ戻す必要があります。
この実機を再現する場合、配線とファームウェアの片方だけを元に戻さないでください。

### 実機で確認した結果

- ユーザー測定：指を置いた直後にENとVCC-Dがそれぞれ約3.2Vへ上昇。
- USBログ：指を置くと `finger detected` を検出。
- UART交換前：起動応答なし、`handshake timeout/error: -116`。
- UART交換後：`boot handshake byte received`、`PS_HandShake OK`、`read enrolled-id bitmap ok` を確認。
- 登録状況読み取り：`valid: true`。この確認操作では指紋を登録・削除していません。
- 通信成功を確認したファームウェア：[b64d120](https://github.com/razilyis/zmk-config-Torabo-chan/commit/b64d120756b4a5378e314f7e10264c9e46e08deb)。
- ローカルの確認ログ：`firmware/zw3021-uart-b64d120/connection-check.log`（Torabo-chan作業フォルダー内）。

実配線の説明はユーザー報告と通信成功結果に基づきます。全ての配線区間をこちらで導通実測した記録ではありません。

## ファームウェア

GitHub Actionsの **Build ZW3021 firmware** → `firmware-zw3021` をダウンロードします。
書き込み対象は **torabo-chan-paw3222-zw3021-usb.uf2** です。
既存の **Build firmware** はZW3021を有効にしない通常版を引き続き生成します。

1. 配線を完了したXIAOをブートローダーに入れます。
2. 上記UF2をXIAOのドライブへコピーします。
3. 再起動後、USBケーブルを接続したままにします。

センサーなし・配線不良でもビルドは成功するため、ビルド成功だけでは実機動作を保証しません。
初回は下記ログでハンドシェイクと登録・照合を確認します。

## ブラウザーから登録

1. ダウンロードした **ZW3021-setup.html** をChromeまたはEdgeで開きます。
   このHTMLはビルド時に固定ドライバーと同じリビジョンから取得します。
2. USBの接続ボタンを押し、XIAOのシリアルポートを選びます。
   他のシリアル端末を開いている場合は先に閉じます。
3. 指スロットを選び、登録を開始して画面とセンサーの案内に従って指を置きます。
4. 指に対応する出力文字列を設定・保存します。最初は機密性のない短い英数字で確認してください。
5. テキストエディターにフォーカスを移し、登録した指を置いて入力を確認します。

出力文字列は最大31文字。英数字（大文字含む）と `! @ # $ % ^ & * ( ) - _ = + . ,` に対応します。
日本語・空白は非対応です。記号のキーコードはUS配列前提なので、PCのJIS配列では記号が一致しない場合があります。
文字列とEnter送信設定は実機へ保存し、GitHubやUF2に埋め込みません。
指紋照合時はその時点の入力先へキー送信します。OSの生体認証として登録される仕組みではありません。

## 確認用ログ

USBシリアルは115200 bpsで確認できます（センサーUARTの57600/8N2とは別です）。
ブラウザーのデバッグ表示、またはシリアル端末で次を確認します。

- `zw3021: initialized`：ドライバー初期化
- `zw3021: serial RPC ready`：ブラウザー用USB窓口の準備完了
- `finger detected` → `VCC-D enabled` → `PS_HandShake OK`：指検出からセンサー通信まで成功
- `enroll stored id=...`：登録成功
- `match id=...`：照合成功

## Keymap Editorとの共存

編集元は従来どおり `config/torabo_chan.keymap` の5キーです。
ビルド時に `scripts/prepare_zw3021.py` がコピーを作り、全レイヤーに内部用54キーを追加します。
元ファイルとC字レイアウトJSONは変更しません。追加したレイヤーも自動処理します。
変換は物理5キーの順序とbindingを保ち、先頭レイヤーへ出力文字のキーコード、他レイヤーへ透過キーを追加します。
各レイヤーが明示的な5つのbindingでない場合は、誤ったUF2を作らずビルドを停止します。

ZW3021保存領域は内蔵フラッシュの0xE4000～0xEBFFF（32KiB）。
ZMKの既存設定領域0xEC000～0xF3FFFとブートローダーは移動しません。
